# 鸭控 · DuckPilot 0.4

Android 横屏手机控制台，包名保持 `com.lucien.microduck_lew`，可覆盖安装此前同签名版本。当前是个人测试签名，适用于 ARM64、Android 7.0 及以上。

## 连接与相机

手机和主板在同一局域网，填写主板自己的地址、控制端口 `20043`、相机端口 `8443`，无需填写密钥。主板需安装匹配的 UDP 接入层，并已有 R17 mediad 摄像头服务：

```bash
sudo bash scripts/install-udp.sh
systemctl is-active robotd mircoduck-udp mediad
```

连接后自动建立只接收视频的 WebRTC 会话。视频占满背景，中央留给画面；两侧使用黑色渐变及视频层内的模糊蒙板。旋转按钮按 0/90/180/270° 循环，只调整手机显示。断开、后台和销毁页面会关闭视频会话，返回前台时重新连接相机。

Android 通过内嵌的本地 WebView 承载 WebRTC，Flutter 绘制悬浮控件。HTML/JS 打包在 APK 中，不加载远程控制网页，不请求手机摄像头或麦克风。WebRTC 数据通道不发送控制命令；动作使用局域网 UDP v2，不再做配对认证。能访问控制端口的设备可以建立控制会话；使用自己的局域网或主板 AP。

## 连接 → 上电 → 站立

- **连接**只读取状态并开启视频，不自动站立或启用策略。
- **上电**自动准备 motion 服务，等待实际模式和反馈就绪；界面不提供标定模式选项。这一步不偷偷执行 HOME，扭矩仍关闭时显示“待站立/已就绪”。
- **站立**调用 robotd 的 `robot.init`，会使能关节并缓慢移动到 HOME，界面统一叫站立。在坐下状态时，站立调用 `sit_toggle` 退出坐姿，避免错误地用 init 与坐姿锁争抢。
- **卸力（原下电）**请求 `robot.relax`，仅释放舵机扭矩，不关主板、不退出 motion、不停止相机；先支撑好机器人。
- **停止**发送零连续输入并结束手机输入租期，保持 robotd 本身的站立/保持策略，不等同于卸力。

没有面向用户的“接管/释放”开关。动作和摇杆在显式操作时内部获取输入租期，实体手柄与其他控制台仍具有原有互斥约束。没有持有摇杆时不会重放失联前的方向；按下的新输入才会准备运动。真实站立/步态和手机安装验收仍需进行。

## 控件

| 位置 | 含义 |
| --- | --- |
| 左摇杆上下 | 前进 / 后退 |
| 左摇杆左右 | 左转 / 右转，不产生横移 |
| 慢 / 中 / 快 | 幅度 35% / 65% / 100%；默认慢档；切档清除当前输入 |
| 右侧短叫 | 单次 chirp 请求 |
| 右侧长叫 | 按住发声，抬手或取消即释放；沿用现有 LT 的嘴巴/声音映射 |
| 底部动作 | 前滚、坐下/站起、捡拾和踢腿；面板可横滑，按钮按实际已加载能力启用 |
| 参数 | 帧率/码率/丢包、IMU 与逐关节真实反馈 |

满幅运动对应 robotd 原有上限：前后 0.3 m/s、转向 1.5 rad/s，再乘档位幅度，保留原有死区。首次明确请求方向或动作时，客户端会请求开启策略；robotd 原有姿态、HOME 和传感器检查继续决定是否接受。

坐下状态来自 `robot.policies.sitting`，能力来自已加载模型；没有数据时不猜测坐下/站起状态。实际动作由 robotd 接受和执行，按钮回执不能当作动作已经完成。

## 构建和验证

```bash
cd app
flutter pub get
flutter analyze
flutter test
flutter build apk --release --target-platform android-arm64
```

显式实机只读检查使用 `MICRODUCK_TEST_HOST`。额外设置 `MICRODUCK_TEST_POWER=1` 会验证上电服务准备，仍不执行站立、使能策略或非零方向。

0.3 历史实测：同一套打包的视频脚本在浏览器收到主板 1280×720、30 FPS 视频并验证 90° 旋转；当时图像较暗，观察窗口无丢包。Flutter 客户端验证上电后为 motion、扭矩 OFF、未 HOME、策略 OFF。ADB 未连接 Android 手机，因此原生 WebView 在真实手机上的运行及运动行为未验收。

0.4 实测：真实 Flutter 客户端无密钥连接当前主板，读取到新鲜 IMU 与全部 15 关节；连接、断开、重新连接通过。安装接入层保留原有扭矩与策略状态，未主动执行站立、卸力或运动。主板 NetworkManager 成功加载生成的 STA/AP 配置，随后删除临时配置，全程未激活或切换网络。

启动图由用户选择，鸭头标识来自 Microduck 官方资产的独立衍生设计；许可与署名见 app/NOTICE.md。请勿公开个人系统镜像等机器凭据。

## 主板终端

安装时同时提供 `duckctl`，完整命令及 STA/AP 切换、确认/回滚流程见 [CLI.md](CLI.md)。App 0.4 必须使用 UDP v2 接入层；此前个人系统镜像尚未重打包，烧回后需要安装 0.4 接入层。
